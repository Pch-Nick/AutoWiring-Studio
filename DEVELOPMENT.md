# DEVELOPMENT.md

## Реализовано (этапы 1–5, частично)
- Vite + React + TS, тёмная/светлая тема, 4-панельный интерфейс, адаптив.
- Библиотека (~100 деталей, 8 категорий из ТЗ), поиск по названию/контактам/числу контактов, избранное, drag&drop и двойной клик, свои компоненты (название + число контактов).
- Редактор на @xyflow/react: контакты-хэндлы (цвет по типу pwr/gnd/sig), провода между контактами, сетка, minimap, zoom, fit, multi-select, copy/paste, Undo/Redo (100 шагов).
- Панель свойств: название, редактирование/добавление/удаление контактов, состояние выключателей, заметки; провод: 12 цветов, HEX, маркировка (+12V, GND…), сечение, толщина, пунктир.
- Раздельные гидравлические выключатели переднего/заднего тормоза (2 контакта, состояние разомкнут/замкнут) и механические концевики — отдельные типы. Симуляция цепи стоп-сигнала (`brakeLampOn`) покрыта тестами.
- Проверка схемы: незадействованные контакты, дубли, замыкание контакта на себя, питание↔масса, нет предохранителя. Пересечение проводов не считается соединением.
- Автосохранение в IndexedDB, восстановление после перезагрузки, экспорт JSON (версия 1) / PNG / SVG, импорт JSON с проверкой Zod (при ошибке проект не меняется).
- README, .gitignore, .env.example, GitHub Actions для Pages.

## Симуляция (src/sim.ts) — этап 5
Кнопка «Симуляция» в шапке. DC-решатель (метод узловых потенциалов, Гаусс): сети из проводов, шины/разветвители/точки соединения, масса, аккумулятор (ЭДС + 0.02 Ом), резисторы, нагрузки (лампы, стартер, насосы, ЭБУ и т.д. — таблица `LOADS`), выключатели (клик по бейджу на детали), реле (катушка 80 Ом, срабатывание ≥50 мА, итерации), предохранители (перегорают при токе > номинала, перерасчёт), диод (идеальный), многопозиционные переключатели (ключ, свет, поворотники). На поле: напряжения на контактах и проводах, ток/мощность детали, свечение ламп, перегоревшие предохранители, КЗ (>150 А). Тесты: стоп-сигнал (передний/задний/оба), возврат на массу, реле стартера, предохранитель, КЗ.
Полярность (плюс/минус берутся из типа контактов pwr/gnd, их можно менять в свойствах): электронные блоки (`POLAR`: ЭБУ, CDI, приборы, GPS, USB, светодиодная лента, ABS…) работают только при правильной полярности, при перепутанной — ток не идёт и выдаётся ошибка «Обратная полярность»; мотор (стартер, насос) при обратной полярности вращается назад — предупреждение; «Нет массы» — на плюсе потребителя напряжение есть, а минус не подключён.
Реле поворотников: `flasher` (3 вывода 49/49a/31, нужна масса) и `flasher2` (2 вывода). Динамическая симуляция: при включённой симуляции и наличии прерывателя идёт часы 100 мс, контакт 49→49a замыкается/размыкается с периодом 0.7 с (`FLASH_HALF`, ≈85 вспышек/мин). Лампы мигают, символ показывает положение контакта. Частота не зависит от нагрузки (перегоревшая лампа не ускоряет мигание).
Ограничения: нет сопротивления проводов (падение напряжения по сечению), нет генератора/конденсатора/DC-DC/регулятора, датчики не моделируются, мигание поворотников (реле) не динамическое, нет переходных процессов, номиналы нагрузок типовые.

## Графические компоненты (src/symbols.ts) — этап «графические схемы», часть 1
Деталь = SVG-символ + координаты контактов на нём + электрическая модель. `resolve(d)` возвращает размер, функцию рисования (учитывает состояние: замкнут/разомкнут, реле, горит, перегорел) и координаты каждого контакта; React Flow Handle ставится ровно в эту точку, провода начинаются в контакте. Номер контакта подписан у точки, в симуляции рядом показывается напряжение. Совместимость: у старых проектов нет координат — берутся из символа по libId; можно переопределить `pin.x/pin.y`. Детали без собственного символа (ЭБУ, приборы, пользовательские) рисуются универсальным блоком-схемой с контактами на рамке.
Свои символы: ранее готовые — аккумулятор, масса, предохранитель, блок предохранителей, лампы, фары/фонарь, выключатели (кнопка, гидравлический с «P», механический, плоский), реле 4- и 5-контактное (30/87/87a/85/86), стартер, генератор, катушка зажигания, диод, резистор, конденсатор, точка соединения, многопозиционные переключатели (ключ, свет, поворотники). Добавлены CDI, реле-регулятор, 5-контактное реле. Библиотека: миниатюры + фильтр Авто/Мото (`domainOf`).
Добавить новую деталь: запись в `LIBRARY` + (по желанию) ветка в `specific()` в symbols.ts + модель в `sim.ts`. Тест проверяет, что у каждой детали контакты внутри рамки и не накладываются.
Управление на схеме (CompNode, только при включённой симуляции): кнопки и тормозные выключатели — пока держите (`MOMENTARY` в sim.ts), выключатели с фиксацией (аварийный, главный, подножка, «аварийка») — клик; ключ, свет, поворотники — клик = следующее положение, «Старт» ключа возвращается в «Вкл» при отпускании. Изменения состояния не попадают в Undo.
Точки излома проводов (WireEdge.tsx, wirepath.ts): двойной клик по проводу — добавить точку; у выбранного провода точки тянутся (привязка к сетке), «+» на середине сегмента создаёт новую, двойной клик по точке удаляет, кнопка «Убрать изломы» в свойствах. Точки хранятся в `wire.data.points` (JSON, старые проекты совместимы), Undo/Redo работает.
Не проверено в живом браузере (pointer-события): перетаскивание точек и удержание кнопок — проверить вручную.
Осталось по этому ТЗ: анимация тока по проводам по направлению, связь рычаг/педаль → гидравлический выключатель, символы для датчиков/ЭБУ/разъёмов/CDI/реле-регулятора вместо блока, сверка с фото схемы мотоцикла (фото не получено).

## Защита от неправильных соединений (src/connect.ts)
`checkConnection` блокирует: провод не к контактам, контакт на самого себя, дубль провода, контакты, уже находящиеся в одной цепи, и короткое замыкание на уровне цепей (цепь с контактом «+» нельзя соединить с цепью, где есть масса — с учётом шин, разветвителей, точек соединения и символа массы). Правила работают при наведении (зелёный/красный контакт), в `store.connect` и показывают причину сообщением на поле. При удалении контакта удаляются его провода; импорт JSON отклоняет проводa на несуществующие контакты. Правила опираются на тип контакта (+/GND/сигн.) — его можно менять в свойствах.
Не проверяется: «разумность» сигнальных соединений (сигнал↔питание), так как тип по названию не определяется.
